# dsh-diagram Star 转化优化设计

## 目标

提升已经使用 DeepSeek Harness 的仓库访客从“看懂项目”到“认为现在有用，并 Star 以便以后找回”的转化。

2026-08-20 的公开基线为 3 Stars、134 位仓库 Overview 独立访客。二者并非 GitHub 提供的逐访客归因，只作为当前约 2.2% 的代理转化率基线。改版后的验收目标是：累计至少 100 位新的 Overview 独立访客后，`新增 Stars / 新增 Overview 独立访客` 达到 5%。

## 第一性原理判断

Star 不是阅读完成度指标。目标访客只有在同时确认以下事实后，才有理由把仓库保留在自己的工具箱：

1. 这是为 DSH 用户解决的真实问题，而不是泛化的 AI 绘图宣传。
2. 它把已经进入 Session 的文章变成可继续编辑的画布，而不是一次性图片或 Mermaid 输出。
3. 从请求到结果、编辑、保存和导出的路径已经真实可用。
4. 安装成本足够低，未来需要时可以快速找回并使用。

当前 README 已有明确功能描述、一行安装和真实 GIF，但 GIF 的前半段大多停留在静止会话，随后直接进入画布，没有完整证明“对话内预览 → 进入编辑 → 修改后保存 → 导出”的结果链。首屏继续增加功能文字不会弥补这个证据缺口。

## 设计方案

采用“价值主张 + 即时证据 + 克制 Star 提示”的首屏结构。

### 信息顺序

英文默认 README 与中文镜像保持相同语义和顺序：

1. 项目名、语言入口和现有 npm、Release、License、DSH 徽章。
2. 一句面向 DSH 用户的具体承诺：DSH Session 已经理解文章；dsh-diagram 把这份理解变成可持续编辑的 Excalidraw 画布。
3. 一句边界说明：Agent 负责初始结构，用户在 DSH 内编辑、自动保存和导出；产物不是一次性 Mermaid。
4. 新的真实 DSH Web 演示 GIF。
5. 最短的一行安装命令。
6. 克制的 Star 提示：如果它适合用户的 DSH 工具箱，可以先 Star，以便下一次处理长文章时找回。
7. 三个首屏利益点：可编辑、对话原生、可保存并导出。
8. Quick install、功能表、安全边界和工程细节继续保留在首屏之后。

Star 提示不得使用虚假稀缺性、社会证明、目标数字、交换条件或自动 Star 链接，也不得暗示插件可以脱离 DSH 使用。

### 演示 GIF

新 GIF 必须来自无隐私数据的真实 DSH Web，不得使用合成界面代替运行证据。录制按以下顺序完成一个连续结果链：

1. 打开已经包含通用文章内容的 DSH Session。
2. 通过 `/canvas-diagram` 或自然语言请求创建 diagram。
3. 显示对话内 inline preview。
4. 从预览进入“画布”标签。
5. 修改一个节点的文字或位置。
6. 显示 `Saved` 状态。
7. 显示 `.excalidraw`、SVG 和 PNG 导出入口。

GIF 应在不超过 15 秒内完成上述链路，裁掉无操作停顿，并保证 GitHub README 常见宽度下仍能辨认预览、画布和保存状态。录制画面不得包含用户工作区路径、历史会话、API key、真实文章或其他隐私信息。

媒体发布到 GitHub `assets` 分支，使用新的带版本语义的文件名，README 引用该新地址；不把 GIF 提交进 `master` 历史。旧素材在新素材公开可访问并通过 README 渲染检查前不得删除或覆盖。

## 范围

本次修改包括：

- `README.md` 与 `README.zh-CN.md` 的首屏文案和顺序。
- `assets` 分支上的新演示 GIF。
- README 中的演示资源地址。
- 实施前后的 GitHub Traffic 与 Star 代理指标记录和交付报告。

本次不包括：

- 插件功能、版本、npm 包、Release 或产品架构变化。
- 泛 AI 绘图工具定位、脱离 DSH 的独立使用承诺。
- 虚假评价、虚假用户数、购买或交换 Stars、批量私信等增长手段。
- 删除 README 中仍影响安装、安全或使用决策的内容。

## 验证

交付前必须完成：

1. 双语 README 的价值、边界、安装、Star 提示和利益点逐项语义对照。
2. README 中所有公开链接和徽章返回有效响应，新 GIF 可从 GitHub raw 地址加载。
3. 在 GitHub README 实际渲染页面检查桌面宽度和窄屏宽度，确认首屏信息层级、GIF 可读性和安装命令换行。
4. 在真实 DSH Web 复核 GIF 所展示的创建、预览、编辑、保存和导出行为，不以剪辑掩盖失败或等待状态。
5. 运行 `git diff --check`；若只修改文档和外置媒体，不运行与代码无关的完整测试套件，但必须如实报告未触及代码。

发布后记录新 Stars 和 Overview 独立访客。只有在新增独立访客达到 100 后才判断是否达到 5% 目标；样本不足时只报告数据，不得宣称转化优化成功。
